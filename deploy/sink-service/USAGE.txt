wind-hub Sink Service v2 batch deployment
=========================================

Process model
-------------
One container starts exactly three OS processes: Main, Realtime, Reliable.
Only Main exposes a gRPC/mTLS endpoint. Both workers have independent
asyncio loops and connect directly to NATS or JetStream for samples.
IPC conveys commands, status and metrics, never sample data.

Prepare a writable persistent configuration root containing:
  configs/services/sink_service.yaml
  configs/instances/sinks.yaml
  configs/instances/deliveries.yaml
  configs/templates/sinks/<name>_<version>.yaml
  configs/templates/deliveries/<name>_<version>.yaml
  tls/ca.crt, tls/sink.crt, tls/sink.key (or adjusted security paths)

Ensure service.config_root and the paths in security match the mounted
runtime filesystem. The volume must be writable by UID 65532; Main
durably stores configuration revisions in .generations/ and CURRENT.
Service file must explicitly specify instance paths and template root.

NATS prerequisites
------------------
Provision a file-backed JetStream WH_HISTORY with subject
  wh.hist.batch.>
and a file-backed WH_DLQ with subject
  wh.dlq
Both require Limits retention, DiscardNew, positive MaxBytes and MaxAge.
Reliable uses stable Durable Consumers per Delivery. A source message is
ACKed only after all matched measurements were confirmed delivered or
durably copied to DLQ. DLQ overflow blocks ACK.
Realtime uses NATS Core subject
  wh.rt.batch.>
and never writes the source to JetStream.

Set NATS URLs in configs/services/sink_service.yaml to reachable broker
addresses (127.0.0.1 from within Docker means the container itself).
Provide TLS certificates as configured and authorize external gRPC clients.

Run
---
export WIND_HUB_SINK_CONFIG_ROOT=/srv/wind-hub/sink
docker compose -f deploy/sink-service/compose.yaml up --build

Web/CLI gRPC target: 127.0.0.1:50061 by default, using mTLS.
One container has one gRPC endpoint; do not run separate realtime/reliable
containers or a second instance against the same Durable and Sink ownership.

Configuration changes
---------------------
Main is the only configuration Writer. Service-level changes require
restart. Instance/Template changes can be applied incrementally where safe.
Reliable Durable source selector changes are rejected without separately
audited migration. STOP persists and is not automatically undone.
A worker restart restores only desired START Deliveries.

DLQ replay
----------
Manual, authorized replay only:
python scripts/sink_dlq_replay.py --server nats://broker:4222 \
  --dlq-stream WH_DLQ --delivery-id <id> --limit 100
Add --execute only after reviewing the dry-run. Malformed split DLQ parts
require manual reconstruction and repair; never auto-replay invalid payloads.
