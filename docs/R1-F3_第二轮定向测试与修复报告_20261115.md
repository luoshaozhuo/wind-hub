## 3. Sink：关闭与 Task 完成回调调度

`tests/sink_service/unit/test_output_pool_cancel_races.py` 原两项重新执行通过：

1. 原生 I/O 取消并隔离后，额度等待者获取额度会再次检查 `unsafe`，不会进入 Adapter。
2. `adapter.close()` 期间发生取消，`release()` 保留 `_entries`、`_physical_quotas` 与隔离状态，要求外部 fencing。

新增参数化测试显式暂扣 `_finish` 完成回调，使其在 close 返回之后才执行，覆盖：

- 正常 Task 已 done、回调未执行：close 依据 Task 实际状态正常回收，不误判永久隔离；回调随后送达不改变裁决。
- Task 已 cancelled、回调未执行：即使 `unsafe` 尚未由回调设置，close 仍保留物理目标并抛 `ConfigurationError`。

该文件最终 `4 passed`。证明关闭判定不依赖回调恰好先运行，而不是只复跑原两个调度顺序。

## 4. Collector：Reliable 整体接纳、容量、并发与停止

`tests/src/component/test_collector/test_publisher_v2.py` 最终 `14 passed`，覆盖：

- 单事件子批数大于队列总容量时立即拒绝，启动消费者后 JetStream 调用仍为空。
- 队列已有其他来源事件时，超容量事件拒绝不会误删或发布自身前缀，既有事件恰好发布一次。
- 剩余空间不足时，完整事件等待足够容量，不能把一个子批塞进唯一空位；最终事件顺序和四子批完整发布。
- 四个并发发布者、每个来源事件两个子批、队列容量 2：全部完整接纳，停止后 8 次 JetStream 发布、8 个 PubAck 样本、队列空且 unfinished=0。
- 既有 Reliable 超时失败、重试身份稳定、Realtime 背压及停止关闭连接测试无回归。

这些测试使用 Fake NATS 仅隔离传输 I/O，队列、锁、Event、停止与计数均运行真实生产实现；不将其表述为真实 NATS 系统测试。

## 5. DG Diagnose 与配套仿真 mTLS

### 5.1 生产 Diagnostics 正反向矩阵

`tests/data_generator/integration/test_gateway_writer_mtls.py` 直接实例化生产 `Diagnostics`，对强制客户端证书的真实 Gateway gRPC 服务验证：

- 合法 CA 与授权 `generator` 主体：grpc 阶段 PASS，验证目标变量数正确。
- 同 CA 但未授权主体：FAIL / `DIAGNOSTIC_FAILED`，不伪造变量证据。
- 独立错误 CA：FAIL。
- 无证书明文连接 TLS 端口：FAIL。
- 非回环地址无 TLS：创建 Channel 前拒绝且不留下 Channel。
- 主机名 `localhost` 无 TLS：同样拒绝；只有数字回环地址可走明文边界。

加上原 GatewayWriter 合法全租约链、Channel 复用等测试，该文件 `8 passed`。真实续期用例仍跨过原 10 秒租约。
