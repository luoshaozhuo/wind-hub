### 3.2 新增确定性 P1

`tests/sink_service/unit/test_output_pool_cancel_races.py` 两项均稳定失败：

1. 物理额度 2，A/B 在途、C 等待；取消 A 后目标 `unsafe=True`，B 正常释放一个额度，C 仍进入 Adapter。期望原生写入 2 次，实际 3 次。根因是 `_start_write()` 只在等待额度前检查一次 `unsafe`，获取额度后没有复查。
2. 在途写入期间进入 `release()` 并阻塞 `adapter.close()`；close 期间取消原生 Task，再放开 close，`_entries` 与 `_physical_quotas` 被删除。后续可重新绑定，违反外部 fencing 前必须保留隔离状态的所有权约束。

这两项必须由 ChatGPT 设计额度等待者唤醒/复查、关闭期间取消与物理隔离保留的统一状态机，本轮不擅自修补。
