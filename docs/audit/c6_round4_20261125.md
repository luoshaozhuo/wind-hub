## 3. 独立代码审查

审查了 `realtime_adapters.py` 的 partition queue、dispatcher、settlement、共享 Future、设备锁、取消、STOP/close、Partition Cache 与结果索引，以及 R14 spawn encoder pool 的预热、绝对时间调度、有界在途和 shutdown。

覆盖证据包括：

- 同 Partition 跨设备真正合并，不同 Partition 独立提交；Record Key/payload 逐字节保持。
- 共享确认失败向各原始请求映射失败；部分提交成功保留已确认零基索引。
- 物理 Builder 成功/失败尝试只计一次，确认点权重无重复计数。
- 同设备锁保持至原生请求终局；调用取消不提前释放锁，quota 取消隔离语义保留。
- close 先停止准入，再等待 partition workers 与 settlements，之后关闭 Producer；R14 encoder pool 有界并 `shutdown(wait=True, cancel_futures=True)`。

本轮未发现可由现有证据确认的 P0 结构缺陷；Fake Producer 结果未被当作真实 Kafka 验收，真实容量与八服务链路另行执行。

### 4.2 D4 未执行原因

Admin API 实测 Broker：`message.max.bytes=1048588`，`socket.request.max.bytes=104857600`。D4 Builder 上限 1048576 距 Broker 单条 RecordBatch 上限仅 12 字节，无法容纳批次头、记录及协议开销，属于不安全配置。**D4 NOT_RUN**，未通过修改 Broker 或 Producer 上限绕过。

## 6. FC04 RAW、数据级别与八服务

```text
Generator → Gateway FC04 → Collector → JetStream → Reliable Sink
→ Kafka JSON v2 RAW → Storage RPC → TDengine payload_bytes
```

- 从 Generator 真值独立计算 FC04 寄存器数据字段字节，Kafka hex 与之一致。
- Storage `payload_bytes` 与 Kafka 逐字节一致。

- Task、sample、batch、PointTable 身份在 Kafka 边界保持；Storage 契约本身不暴露 task_id，未伪造该字段。
- RAW 仍仅指寄存器数据字段，不扩大为完整 Modbus ADU。

八服务最终 **6 passed**，包含 PROTOCOL provenance、Storage 重启回读、四 Sink 输出、Commander AGC/AVC APPLIED 与 FC04 RAW。PROTOCOL/BUSINESS projection 及数据级别契约回归通过；BUSINESS 全链独立逐值对账未在本轮新增。
