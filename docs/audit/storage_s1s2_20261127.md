## Kafka 消费流水线

`test_kafka_retry.py` 连续三次均 **25/25**，`test_kafka_real.py` 真实故障恢复 **1/1**。Storage 单元组件最终 **277/277**。

已验证：

- Poll 与数据库写入重叠，跨 Poll 进入有界缓存，连续 Offset 合批；分区并行且同分区 FIFO。
- 行数/字节预算、真实背压与解除后恢复 Poll；Buffer Rows/Bytes 包含排队和执行中数据，异常/停止后归零。
- 仅提交可靠持久化的连续前缀；commit 失败重放、broker 重启、rebalance 和旧 Generation 不提交。
- worker permit 等待期间发生 rebalance 或游标回退时，旧批不越过新游标；未提交 fetch 不被静默跳过。
- TDengine 失败/UNKNOWN、部分成功、Kafka commit 异常、dispatcher/TaskGroup 异常均 fail-closed。
- 正常 STOP 按“停止 Poll → 排空 admitted batch → 持久化 → commit → close”执行；超时安全取消，不提前宣称成功。
- 重复竞态运行无新增任务泄漏；Fixture 使用 admitted buffer 状态而非单独 `asyncio.sleep()` 猜测顺序。

当前架构瓶颈不在 Kafka 接口契约本身，而在后续生产写入/调度/确认链路的持续容量。
