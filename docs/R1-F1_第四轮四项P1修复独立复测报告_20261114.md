## 6. 新发现缺陷

### R4-01：COMMIT 后同请求续期 epoch 重试被误判为异内容冲突

- 级别：**P2（恢复可用性/幂等性；fail-closed，不是越权解除）**
- 状态：**OPEN，移交 ChatGPT/生产实现方**
- 位置：`src/commander/infrastructure/event_repository.py:483-504`，调用路径 `service_lifecycle.py:381-395`
- 回归测试：`test_same_request_after_commit_window_failure_accepts_renewed_epoch`
- 实测结果：第二次 `RecoverDeviceControl` 返回 `ALREADY_EXISTS`，设备保持 BLOCKED，旧 UNKNOWN 不变、现场写为 0。

复现步骤：

1. 首次证明返回 token=T、epoch=E，SQLite COMMIT 成功；
2. 第二次核验撤销或其他失败，本地不解除，设备继续 BLOCKED；
3. 同一 caller/request_id、相同证据和 token 重试，证明方在同一控制权下合法续期为 epoch=E+1；
4. `commit_recovery` 将已存 epoch=E 与新证明 epoch=E+1 纳入同一整组相等比较，抛出 `FileExistsError`，RPC 映射为 `ALREADY_EXISTS`。

该比较在第三轮基线已存在，本轮新测试揭示边界，不认定为第四轮新增生产回归。它不妨碍四项 P1 的 fail-closed 修复，但与 v1_42 同控制权 epoch 可增长及请求幂等恢复语义不协调。如何区分合法续期与异内容冲突、是否以及如何更新持久裁决和 Outbox，属于持久化/契约设计，验收方未自行修改。

除上述 P2 外，本轮未发现新的 P0/P1。
