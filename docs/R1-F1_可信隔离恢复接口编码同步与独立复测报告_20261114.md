## 2. 基线审查结论

`a1bc0ce9` 已声明新的 Unary RPC 和请求/响应消息，服务端方法先检查 `recover` scope，再检查必填字段、request_id UTF-8 长度和证据字节数，最后**无条件**以 `FAILED_PRECONDITION` 终止。实现没有调用证明方、恢复裁决服务或 `QueuedExecutor` 解除路径。

因此它是诚实的 fail-closed 接口占位，不是可信恢复实现。传输认证、证书权限、证据非空或格式可解析均未被当成物理隔离事实。

## 6. 参数、大小、伪造/过期/重放证据与状态不变性

真实 RPC 参数化验证：空/空白 device_id、空 expected_revision、空 request_id、129 字节 ASCII request_id、129 字节多字节 UTF-8 request_id、空证据、65537 字节证据均为 INVALID_ARGUMENT；65536 字节证据通过大小检查后仍因无证明方 FAILED_PRECONDITION。

在真实 SQLite 中预置未终结命令并启动服务，使其恢复为 UNKNOWN、WT01 BLOCKED、服务 DEGRADED。随后经真实 mTLS 分别提交：

1. 任意二进制伪造材料；
2. 内容为伪造 issuer 和 2000 年过期时间的材料；
3. 相同 request_id/证据的重放。

三次均 FAILED_PRECONDITION，且逐次请求后：

- 原命令 state/outcome 均保持 UNKNOWN；
- WT01 仍 BLOCKED、服务仍 DEGRADED；
- retained permits 与 settled-unknown 集合前后不变；
- 真实 Modbus 模拟器写计数为 0；
- 停机如实返回 `{'WT01'}`。

这证明当前拒绝路径不解除阻断、不释放额度、不改写 UNKNOWN、不重发现场写入；不证明未来成功路径安全。

## 7. 错误与日志敏感信息

服务端错误只返回固定参数错误或“independent isolation attestation verifier is not configured”，不回显证据、不返回解析内容。专项对 RPC details 与 `caplog` 检查敏感证据文本均未出现。

CLI 输出只包含服务端响应摘要/错误封装，不输出请求证据。二进制用例含 NUL、0xff、0x80，线载荷逐字节等于原文件；输出不包含证据原文。未读取或输出任何 `.env.local` 敏感值。

## 8. CLI 独立验证

实际执行 `wind-hub commander recover-device --help` 退出 0，显示全部必填参数：`--device-id`、`--expected-revision`、`--request-id`、`--attestation-file`。

`tests/cli/test_recover_device.py` 共 10 项通过：

- 二进制证据经 Base64 JSON-Protobuf 映射后在真实 gRPC 线载荷中还原为原始 bytes；
- BLOCKED 响应为 FAILURE/退出 1；
- FAILED_PRECONDITION/PERMISSION_DENIED/UNAVAILABLE/INVALID_ARGUMENT 分别非零退出；
- 缺失、空、65537 字节文件非零且不发 RPC；
- 65536 字节文件未被本地大小边界误拒，最终仍按服务端失败退出；
- 文件缺失不再暴露未处理 traceback；
- 读取上限为 65537 字节，不会为判断超限先把任意大文件全部读入内存。

BLOCKED 响应解析使用真实 gRPC 测试服务器注入响应，只验证客户端退出码，不冒充生产解除成功证据。

## 9. 尚未实现的生产能力（F1-GAP-02，P1，OPEN）

以下能力在当前源码中均不存在，不能由本轮拒绝测试或任何 Mock 成功替代：

1. **独立可信证明方适配器及部署信任配置**：无 Infrastructure Port、信任根、真实证明方客户端。
2. **证据真实性与安全绑定验证**：无签名、颁发者、设备/旧实例/新实例绑定、配置修订、fencing epoch 单调性、时效、撤销、token 防重放验证。
3. **旧实例现场 I/O 的外部证明**：无部署层独占控制权或现场安全隔离事实核验；mTLS/签名存在本身不构成该证据。
4. **恢复裁决与结构化审计可靠持久化**：无请求指纹、证据摘要、operator、epoch、decision_id、审计 Outbox 的受控事务提交，也无同 request_id 不同内容拒绝的持久幂等实现。
5. **证据复核后的合法解除 BLOCKED**：RPC 未接 QueuedExecutor，不存在真实 UNBLOCKED 生产返回路径。
6. **恢复后 DEGRADED→READY 完整真实链路**：由于前项不存在，无法验证所有阻断解除后 Watchdog 提升 READY 的恢复 E2E。

这些需要新的安全证据权威、持久化事务和明确控制权实现，超出本轮允许的小范围接线，不在验收方自行设计不可信放行。
