## 2. 生产修复

位置：`src/commander/infrastructure/event_repository.py:467-537`，新增判断位于 `:506-509`。

`commit_recovery` 已在 `EventRepository._transaction` 的 `BEGIN IMMEDIATE` 事务内读取原请求裁决及设备最大持久 epoch。本次仅在同一请求的幂等分支增加授权有效性判断：

- 同 caller/request_id 的设备、配置修订、证据摘要或 token 不同，继续以 `FileExistsError` 拒绝内容冲突；
- incoming epoch 小于该请求原 epoch，继续以 `ValueError` 拒绝倒退；
- **设备最大持久 epoch 大于该请求原裁决 epoch 时，以 `ValueError("recovery request was superseded")` 拒绝旧请求；**
- 只有设备最大持久 epoch 仍等于原裁决 epoch，才允许同身份、同证据、同 token 的合法 epoch 增长，并返回原 decision_id。

修复比较的是持久化最新裁决与原请求裁决的控制权代次，不是只比较 incoming epoch 与 `MAX(fencing_epoch)`。更大的续期 epoch 无法复活已被其他请求超越的旧授权。

读取、判断和返回均处于原有 SQLite 写事务内，没有引入事务外预检查或新的竞态窗口。失败发生在任何 INSERT/UPDATE 之前，不覆盖历史裁决或 Outbox，不重复生成成功裁决，不改变 UNKNOWN，也不解除 BLOCKED。

v1_43 §13.1.2 已明确规定“最新设备 epoch 未超过该原始裁决”才允许续期，以及“另一决策已提交更高 epoch，必须拒绝旧请求”。本次是实现缺陷修复，不是持久化规则调整，因此设计版本保持 v1_43。
